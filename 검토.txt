# AI 애플리케이션 배포 개요 및 전략

## 1. 개요
AI 모델(GPT, Claude, Gemini 등)을 활용한 사내 애플리케이션은 대부분 Python 기반으로 개발됩니다. 개발이 완료된 후 이를 타 부서나 팀원들에게 배포할 때, 사용자의 PC 환경(Python 설치 여부 등)에 구애받지 않고 원활하게 실행되도록 만드는 '배포 전략'이 필수적입니다.

일반적으로 파이썬 스크립트는 **PyInstaller**를 통해 단일 실행 파일(EXE)로 묶어 배포하는 것이 가장 쉽고 보편적입니다. 하지만 사내 환경에서는 **잦은 프롬프트/UI 업데이트, 사내망 API 연동, 소스코드 유출 방지, 퇴사자 권한 회수** 등 복잡한 요구사항이 발생합니다.

본 문서에서는 기본 배포 방식(PyInstaller)의 한계를 짚어보고, 이를 해결하기 위해 고안된 두 가지 특수 배포 방식(**Streamlit 하이브리드 배포**, **Confluence 기반 보안 배포**)의 아키텍처와 명확한 장단점을 비교합니다.

---

## 2. 기본 배포 방식: 일반 PyInstaller 빌드

가장 직관적이고 널리 쓰이는 방식입니다. Python 인터프리터와 모든 라이브러리를 하나의 `.exe` 파일로 압축하여 배포합니다.

* **적합한 대상:** 보안이 전혀 중요하지 않고, 업데이트할 일이 거의 없는 단순 1회성 유틸리티 스크립트.
* **🟢 장점 (Pros)**
  * **단순성:** 빌드 명령줄 한 줄이면 배포 준비가 끝납니다.
  * **독립성:** 사용자는 Python 설치 없이 더블클릭만으로 실행할 수 있습니다.
* **🔴 단점 (Cons)**
  * **업데이트 지옥 (재배포 필수):** 오타 하나, 프롬프트 한 줄을 수정해도 매번 수십~수백 MB의 EXE 파일을 새로 빌드하여 사용자들에게 다시 전달해야 합니다.
  * **보안 취약성:** 디컴파일 도구(예: `pyinstxtractor`)를 사용하면 1분 만에 원본 소스코드와 API 키가 그대로 노출됩니다.
  * **통제 불가:** 파일이 외부로 유출되거나 퇴사자가 USB로 복사해 가면 실행을 막을 방법이 전혀 없습니다.

## 3. 특수 배포 방식 1: Streamlit Cloud + 사내망 Relay EXE (참조: [4.3.2.4.1])

UI와 비즈니스 로직은 외부 클라우드(Streamlit)에 웹으로 배포하고, 사내망 API(HMG 게이트웨이 등) 호출만 사용자 PC의 가벼운 'Relay EXE'가 담당하는 하이브리드 웹 배포 방식입니다.

* **적합한 대상:** 챗봇, 데이터 대시보드 등 **UI/UX 변경과 프롬프트 튜닝이 잦아 실시간 업데이트가 생명인 AI 앱**.
* **🟢 장점 (Pros)**
  * **압도적인 유지보수성 (재배포 완전 면제):** 이 방식의 **최대 장점**입니다. 개발자가 코드를 수정하고 GitHub에 `git push`만 하면, 사용자는 브라우저 새로고침만으로 즉시 최신 버전을 사용할 수 있습니다. 사용자에게 파일을 다시 보낼 필요가 전혀 없습니다.
  * **뛰어난 접근성:** 사용자는 무거운 프로그램 설치 없이 웹 브라우저 링크만으로 앱에 접속할 수 있습니다. (최초 1회 통신용 Relay EXE만 다운로드)
  * **소스코드 은닉:** 핵심 로직과 프롬프트가 클라우드 서버에 존재하므로 사용자 PC에는 소스코드가 남지 않습니다.
* **🔴 단점 (Cons)**
  * **실행의 번거로움:** 앱을 사용하는 동안 백그라운드에 반드시 Relay EXE 콘솔 창을 켜두어야 사내 API 통신이 가능합니다.
  * **네트워크 종속성:** 사내망(VPN)에 연결되어 있지 않으면 내부 API 호출이 불가능하여 앱이 정상 동작하지 않습니다.

## 4. 특수 배포 방식 2: Confluence 기반 HWID 보안 EXE (참조: [4.3.2.4.2])

Nuitka를 이용해 Python 코드를 C 기계어로 컴파일하고, 사내 Confluence 페이지를 인증 서버로 활용하여 기기 귀속(HWID) 및 실시간 권한 제어를 수행하는 최고 수준의 보안 배포 방식입니다.

* **적합한 대상:** 핵심 알고리즘이나 민감한 데이터가 포함되어 **소스코드 유출을 원천 차단**해야 하며, **사용자 접근 권한을 엄격하게 통제**해야 하는 사내 핵심 툴.
* **🟢 장점 (Pros)**
  * **완벽한 소스코드 보호:** 코드가 C 기계어(.pyd)로 변환되므로 역공학(디컴파일)이 사실상 불가능합니다.
  * **실시간 킬 스위치 (권한 제어):** 별도의 라이선스 서버 구축 없이, Confluence 표(Table)에서 특정 사용자의 상태를 'INACTIVE'로 바꾸는 즉시 해당 사용자의 앱 실행이 차단됩니다. (퇴사자 관리 용이)
  * **기기 귀속 (HWID):** 등록된 PC의 메인보드/CPU 정보가 아니면 실행되지 않아, USB를 통한 무단 복사 및 외부 유출 시도를 무력화합니다.
* **🔴 단점 (Cons)**
  * **업데이트 지옥 유지 (재배포 필수):** 코드가 수정되면 무거운 C 컴파일 빌드 과정을 다시 거쳐야 하며, 완성된 EXE 파일을 사용자에게 매번 다시 배포해야 합니다.
  * **높은 빌드 난이도:** 초기 환경 세팅(Visual Studio Build Tools, Nuitka 등)이 무겁고 복잡하며, 빌드 시간도 오래 걸립니다.

수정 포인트 요약:

Streamlit의 장점 극대화: '재배포 완전 면제', '압도적인 유지보수성'이라는 키워드를 사용하여 Git Push만으로 즉시 업데이트되는 장점을 가장 크게 강조했습니다.
PyInstaller의 단점 명확화: 단순히 '업데이트 불편'이 아니라 '업데이트 지옥', '보안 취약성(1분 내 뚫림)' 등 실무에서 겪는 치명적인 단점을 직설적으로 표현했습니다.
보안 EXE의 장단점 대비: 완벽한 보안과 킬 스위치 기능을 제공하지만, 여전히 '재배포 필수'라는 단점을 안고 있다는 점을 명확히 비교했습니다.
비교 테이블 개선: '최우선 가치'와 '업데이트 방식' 행을 추가/강조하여 한눈에 각 방식의 차별점이 보이도록 구성했습니다.
