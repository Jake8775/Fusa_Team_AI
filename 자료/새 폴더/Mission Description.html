Mission Goal

기능안전검증팀은 차종별 Gate / P2 이벤트 일정을 관리하고, 이를 기반으로 월별 준비 일정 확인 및 JIRA 점검 티켓 조회/업데이트를 수행해야 합니다.

본 미션에서는 다양한 입력자료에서 일정 정보를 추출하고, 이를 확인/수정한 뒤 Confluence에 반영하고, 차종별 타임라인 및 JIRA 연계를 지원하는 실행 가능한 Desktop App을 구현하는 것을 목표로 합니다.

Scenario

관련 일정 정보는 이메일(아웃룩 드래그), PDF, 이미지, 텍스트, 엑셀 등 다양한 형식으로 전달될 수 있습니다. 사용자는 입력자료에서 추출된 일정 후보를 검토한 뒤, 이를 Confluence 기반 저장소에 반영하고, 차종별 타임라인 및 월별 이벤트 조회 화면에서 관리할 수 있어야 합니다.

Required Inputs

  • 이메일 메시지 (아웃룩 드래그)
  • PDF
  • 그림파일 (JPG, PNG)
  • 텍스트 선택 및 드래그
  • 엑셀 파일

App 내에는 위 자료를 받을 수 있는 Drag & Drop Zone이 포함되어야 합니다.

Allowed Tools / Tech

Core Functional Requirements

1. 일정 정보 추출
입력자료로부터 차종, 이벤트(GATE-3 / GATE-4 / GATE-5 / P2 / LP2 등), 담당자 및 일정 정보를 추출할 수 있어야 합니다.
2. 일정 추출 후보 관리
입력자료별로 일정 추출 후보를 확인/수정할 수 있어야 하며, 후보는 차종 / 이벤트 / 담당 + 복수 일정 항목 구조로 다룰 수 있어야 합니다.
3. Confluence 반영
확정된 일정은 Confluence 특정 페이지를 기준 저장소처럼 활용하여 반영할 수 있어야 합니다.
※ URL은 https://hmg.atlassian.net/wiki/spaces/RND/pages/604243425/ 하위의 각 그룹별 페이지를 참고하세요
4. 차종 게이트 이벤트 타임라인
차종별 1라인 형태의 타임라인으로 표현되어야 하며, 화면에는 최소 2개월 수준의 기간 흐름을 확인할 수 있어야 하고, "◀ 2026-07 ▶" 과 같은 이동 버튼을 통해 기간을 이동 가능해야 합니다. 이 경우 차종 클릭 시 우측의 JIRA 조회가 연동되어야 합니다.
5. 월별 이벤트 조회 및 JIRA 연계
"◀ 2026-07 ▶" 과 같은 이동 버튼에 따라 X월 이벤트 조회가 가능해야 하며, 특정 차종 선택 시 관련 JIRA 목록 조회 및 티켓 상세보기가 가능해야 합니다. 상세보기에서는 티켓의 각 필드 속성(Key, 단계, 점검유형, 시스템, 상태, 담당자 등)이 조회되어야 하며, Attachment 영역에 파일 드래그 앤 드롭이 지원되어야 합니다. 단, 저장 버튼 클릭 시 아래 제한 메시지가 표시되어야 합니다:
⚠ 저장 기능 제한 안내 (UI 표시 문구)
"저장 기능은 현재 제한됩니다.
연결된 JIRA는 운영(Live) 서버로, 실제 데이터의 추가·수정·삭제 기능은 구현할 수 있으나 테스트 및 실제 호출은 허용되지 않습니다.
티켓 조회 화면은 실제 웹 브라우저 티켓보기와 속성 및 형식이 일치해야 합니다. 조회화면에서 사용자 입력은 허용하나, 실제 저장 버튼은 Disable 되어야 합니다."

Data / Storage Notes

  • Confluence는 차종당 1 Row 구조의 마스터 페이지를 기준 저장소처럼 활용합니다.
  • 이벤트별 세부 일정은 항목명: 값 형식으로 저장될 수 있습니다.
  • 입력자료 반영 이력은 별도 Import Log 구조로 관리할 수 있습니다.

Business Rules

  • 일정 항목은 일반적으로 아래 순서를 따릅니다.
    제출요청 → 실무회의 → 예비회의 → 본회의
  • 일정이 일부만 확인된 경우에는 확인된 항목만 반영 가능합니다.
  • 본회의만 확인된 경우에는 본회의 1개월 전 제출요청(예상)을 활용할 수 있습니다.
  • 자료 제출 마감은 기본적으로 실무회의 1주 전 기준으로 활용할 수 있습니다.

Implementation Notes

  • UI는 App 목적에 부합한다면 자유롭게 구성 가능하고
  • 편의 기능 또는 기능 향상을 위한 추가 기능은 허용됩니다.
  • 예: 테마, 검색, 필터, 정렬, 검증 보조, 로그 관리, 설정 화면 등

Hint

  • 하나의 문서에 여러 일정 fact가 포함될 수 있으므로, 차종 / 이벤트 / 담당 + 복수 일정 항목 구조를 먼저 정의해보세요.
  • Confluence에 저장할 형식과 App 내부 공통 데이터 구조를 먼저 정하면 구현과 통합이 쉬워집니다.
  • 여러 명이 협업할 경우, 기능 분담보다 먼저 서로 주고받을 데이터 형식을 정해보세요.
  • 예: 입력/추출 후보, Confluence 반영, 타임라인/월별 조회, JIRA 연계를 나누되 공통 데이터 구조는 먼저 합의하는 것이 좋습니다.
  • 샘플 차종 2~3개를 먼저 고정하면 병렬 구현과 통합이 수월합니다.
  • 입력 → 후보 확인/수정 → Confluence 반영 → 타임라인 조회 → JIRA 연계의 핵심 흐름이 자연스럽게 이어지도록 구성해보세요.
  • 패키징 제출을 고려하면, 실행 파일 생성 가능 여부를 중간에 한 번 확인해보는 것이 안전합니다.
